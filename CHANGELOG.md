# Changelog

## 1.0.0

- Integrated Silent Payment recognition into Electrum's existing Send tab;
  `sp1`, `tsp1`, and BIP21 `sp` recipients now use the normal Pay to, Amount,
  Description, Paste, and Pay controls instead of a separate dialog.
- Kept the New Transaction send preview compact with abbreviated reusable and
  derived addresses, while final transaction details wrap both complete
  addresses into aligned 42-character output-column lines. The association is
  stored as public wallet-local metadata and restored after restarting
  Electrum.
- Kept History descriptions concise instead of embedding two long addresses;
  the user's Description is preserved, with `Silent Payment` used when empty.
- Fixed an Electrum 4.8.0 crash when clearing the Send tab after a Silent
  Payment. The plugin no longer calls Electrum's native field updater while
  its payment identifier is temporarily unset.
- Added the Silent Payments SVG mark to the Electrum plugin manifest.
- Enabled both mainnet and test networks after running the complete offline
  construction, sealing, signing, receiver-derivation, signature-verification,
  and serialization harness on each network under Electrum 4.6.0, 4.7.2,
  and 4.8.0.
- Added a separate explicit risk confirmation before any mainnet transaction.
- Retained strict `sp`/`tsp` network separation and all BIP352 1.1.1
  conformance checks.
- Added a self-contained receiver, backup-validation, transaction-scanning, and
  BIP341 recovery utility for controlled end-to-end tests. Receiver files
  cannot be overwritten, mainnet generation requires an explicit risk flag,
  and recovery signatures are verified against Electrum 4.6.0, 4.7.2, and
  4.8.0.
- Kept receiver files and Silent Payment addresses generated by earlier
  unpublished 1.0.0 builds compatible, with a fixed legacy-file regression
  test.

## 0.3.0

- Disabled mainnet transaction creation; this experimental release runs only
  on Electrum testnet, signet, and regtest.
- Lowered the declared minimum to Electrum 4.6.0 after testing the complete
  offline testnet transaction lifecycle under the official 4.6.0 and 4.7.2
  AppImage runtimes.
- Established Electrum 4.5.8 as the lower incompatibility boundary: that
  runtime does not provide the `electrum_ecc` package required by the plugin.
- Added explicit network and SIGHASH_ALL assertions to the integration evidence.

## 0.2.0

- Updated conformance target to BIP352 1.1.1.
- Added BIP21 `sp` payment-instruction parsing, including URI amounts.
- Added forward-compatible parsing for address versions 1 through 30 while
  continuing to reject incompatible version 31.
- Added the complete upstream BIP352 1.1.1 vector corpus and automated all
  sender cases within the plugin's documented single-recipient, compressed-key
  software-wallet scope.
- Added a protocol conformance matrix and SilentPayments.xyz listing template.

## 0.1.0

- Initial experimental sender-only BIP352 implementation.
- Dedicated Qt send dialog for a single silent-payment recipient.
- Strict Bech32m, HRP, version, payload-length, and public-key validation.
- Standard deterministic software wallet and eligible input checks.
- Post-coin-selection derivation, non-RBF enforcement, and pre-sign integrity
  verification.
- Curated BIP352 vector tests and deterministic release builder.
- Headless integration harness using Electrum 4.8.0's real wallet,
  transaction, signing, Bech32m, and secp256k1 implementations.
